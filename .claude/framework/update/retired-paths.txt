# Retired paths — the v2 migration deletion list (TASK-166)
#
# Read by migrate-v2.sh: every path here is DELETED from the consumer
# project during the v1 → v2 migration, then recorded in the tombstone
# (.claude/.migrate-v2-tombstone) so the v2 updater never resurrects or
# re-prunes it. At v2.1 (the drop release) these entries also leave
# framework-manifest.txt upstream.
#
# Grammar = framework-manifest.txt's: trailing slash marks a directory
# (deleted recursively), no slash marks a single file. Comment lines and
# blanks are ignored. Every path is validated project-root-relative before
# use (same escape guard as the updater).
#
# Derivation: CORE-DESIGN.md §1 "Retired at v2.1 / dev-repo-only" +
# framework-manifest.txt. Replacements: capability plugins (advisors,
# council, media, devhooks, console) + the ccmaf core plugin + the
# ccmaf-kernel guard (D1-a).
#
# ⚠ v2.1 AUTHORING RULE (panel finding, sol B1 — protects consumers who
# skip v2.0 entirely): the drop release removes these paths' manifest
# ENTRIES but MUST KEEP THE FILES in the upstream repo. A pre-bridge (v1)
# updater that jumps straight to v2.1 processes the retired paths as
# local-only manifest entries — with the files still present upstream it
# MIRRORS them (harmless, stays v1); with the files deleted it would PRUNE
# them, guard included, with no plugin replacement and no refusal gate in
# its old code. Physical deletion of the files upstream is deferred until
# the v1 fleet is confirmed gone (a v3-era decision).
#
# NOT listed (deliberately):
#   - .claude/hooks/statusline.sh — MOVED (not deleted) by migrate-v2.sh to
#     .claude/statusline.sh (consumer scaffold; CORE-DESIGN §1), then
#     tombstoned by the script itself.
#   - .gitattributes, docs/README.md, docs/*/.gitkeep — ownership transfers
#     to the consumer at v2.1 (dropped from the manifest, never deleted).
#   - .claude/framework/docs/requirements|specs|archives|plans — consumer
#     project content; only the two framework files below are removed.
